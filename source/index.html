Source Code

Homelab Pulse is open core. The app’s core, the agent on your server and the push relay are free software: you may use, study, change and share them. Only Pro, sold in the Google Play edition, is closed.

01 What is open

Each part and its license

Both editions are built from the same code: a fix is written once and reaches both on the same day.

  1. The app’s core GPL-3.0-only

    Everything the app does without Pro: monitoring, containers and services, logs, the terminal, alerts, remote access and invites.

    You may run, study, change and share it. A changed version you share goes with its source, under the same license. The GNU General Public License v3.0

  2. The agent, its API and the push relay Apache-2.0

    What runs on your server, all of it, with every capability for every user. It runs with privileges there, so you can read every line of it.

    You may use, change and ship it, in a closed product too, keeping its license and notices. The Apache License 2.0

  3. Pro closed

    The features Pro opens, and the Google Play edition’s own code that sells it, are not published, and these licenses do not cover them.

  4. The libraries inside the app their own licenses

    Each keeps its own license. The app lists every one with its license’s full text, under Settings › About › Every library and its license.

03 Building

Build it yourself

From the top folder of the source code.

  1. The agent

    With Go 1.27 or later: its tests, then one static binary, agent/bin/hlpulse-agent.

    cd agent
make test
make build

  2. The app

    With JDK 21 and the Android SDK: the community edition, as a debug APK.

    cd android
./gradlew assembleDebug

    Push notifications need a Firebase project of your own, its google-services.json in android/app. The app builds without it.

04 Contributing

Help make it better

Issues and focused pull requests are welcome once the repository is public, with the first release.

  1. Issues

    A bug or an idea, in the open. Say what you did and what you saw, with the app’s version and the agent’s.

    Open an issue

    Issues open with the repository, at the first public release.

  2. Pull requests

    One focused change each, opened on the community repository. Once it is reviewed there, line by line, the project takes it into the code both editions are built from, and its commits come back to the community repository under your name.

  3. The contributor agreement

    Your first pull request asks you to sign a contributor license agreement (CLA), once. It lets your change ship in the Google Play edition too, beside Pro.

  4. A security problem

    Never in an issue or a pull request: report it privately.

    How to report it

05 Ground rules

What a change passes

The repository’s CONTRIBUTING.md has the whole list.

Commits
Conventional Commits, such as feat(agent): … or fix(android): ….
The app
Kotlin’s official style, ktlint and detekt clean. Every text in English and in Arabic, every screen checked light and dark, right to left and left to right.
The agent
gofmt, go vet, golangci-lint run and go test -race ./... pass.
Security
No secret in a log. A new action goes on the agent’s allowlist, with an audit entry. Secrets are write-only through the API.
Decisions
A change to the architecture comes with a decision record in docs/adr/.
