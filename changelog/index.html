Changelog

Every change to the app, the agent and the push relay, newest version first. Both editions of the app share each version number.

1.0.0

The first public release.

This version has not been released yet: what follows is what it will hold.

App

  • A health verdict leads the home screen: one sentence (“All good” or “2 issues need your attention: …”) and a score from 0 to 100, built from the active alerts and pending security updates, with each issue leading to where it can be looked into.
  • Live dashboard: CPU, memory, temperature, storage (with SMART health) and network, with history from 1 hour to 30 days, and each network interface’s traffic today and yesterday.
  • Docker containers and systemd services: status, health, resources and logs; start, stop and restart with confirmation; a cleanup preview that shows exactly what will be removed.
  • Terminal over the authenticated agent connection, with Arabic-aware rendering, sessions that survive dropped connections, editable quick commands and a full-screen mode.
  • Alerts: rules evaluated on the server, end-to-end encrypted push notifications, and Telegram through your own bot.
  • Homelab insights: backup freshness, custom HTTP/TCP checks, apt and image updates, fail2ban/UFW and logins, Cloudflare Tunnel health and Uptime Kuma monitors.
  • Remote access through Cloudflare Tunnel and Cloudflare Access, set up from one API token, with automatic switching between home and away and a connection doctor.
  • Several servers, members and devices with scoped roles (viewer, operator, admin), one-time invites, instant revocation and an audit log.
  • Invites can end after a day, a week or a month, and decide whether the phone may connect away from home. Each phone renews its own key every 30 days and right after a backup is restored; an admin can rotate the shared Cloudflare Access key while the old one keeps working for a week.
  • Guided setup wizards for every integration, each linked to an illustrated guide.
  • Home-screen widget and Quick Settings tile; list-detail layouts on tablets and foldables.
  • Encrypted backup of servers and settings to move to a new phone.
  • Sensitive actions (a new terminal, stopping or restarting, cleanup, power, alert rules, integrations, checks, invites, devices and remote access) are confirmed with the fingerprint or screen lock, and the server itself checks it: the phone signs each one with a key that never leaves its secure hardware, so a copied token cannot act alone.
  • App lock that hides the app behind it, from the screen, from TalkBack and from the recent-apps preview, and locks at once or after 1, 5 or 15 minutes; the widget and the Quick Settings tile still show their summary.
  • Arabic-first, fully mirrored interface plus English; light and dark themes, accent colors, wallpaper colors; tested at 200 % text size.
  • Every error explains its probable cause and the fix.
  • Optional, scrubbed crash reports that travel through your own agent.
  • Removing your last server deletes the push token and the Firebase installation identifier at Google, once the phone has a network, and every copy of the token on the phone; exported backups never carry the token, and the widget keeps its short note of what it showed only while it is on the home screen.

Agent

  • A single static binary for Linux arm64 and amd64, installed as a systemd service under its own user, with Debian packages and an install script that checks the release’s Sigstore signature (cosign) and checksums and takes every other file from the verified binary.
  • No sudo for the agent: a small root helper does the few privileged things the configuration allows (drive health, firewall status, actions on allowed units, reboot, the terminal’s login shell), so the agent itself runs locked down (systemd exposure 1.7). Docker is reached through a filtered API instead of the docker group: creating containers or exec is refused.
  • Pairing by QR code with a pinned TLS certificate, 256-bit device tokens stored hashed, rate limits, and a second listener reserved for Cloudflare Access.
  • Step-up for sensitive actions: without a fresh, single-use signature from the phone’s hardware key over that very request, the agent answers 428.
  • History in SQLite, alert evaluation and notification while the phone is asleep or offline.
  • Daily traffic per network interface, counted from the kernel’s counters and kept across agent restarts and reboots.
  • Write-only, encrypted storage for integration secrets.
  • Custom checks keep their credentials on the server: the app sees a check’s URL or address with its user, password and secret query parameters (?token=) masked as ***, and a command check’s program alone unless the configuration lets it see the command line (show_command), with credentials in common forms masked. The agent says so (the checks-masked capability), so the app can tell it from an older agent that sends targets whole. A command check written as one item (["mysqladmin -p… ping"]), which never ran, no longer goes unnoticed: the agent starts without it, logs a warning that leaves the command out, and the app lists it as an invalid configuration.
  • Least privilege for every device: the whole system journal is for admins, while viewers and operators follow the services the app shows them; caps on open connections and log streams per device and per agent keep a reconnecting phone from exhausting the server.

Relay

  • Pulse Relay forwards end-to-end encrypted push notifications to Firebase Cloud Messaging without seeing their content; it can run as a Cloudflare Worker or self-hosted next to the agent.
